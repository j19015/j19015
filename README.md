## 🚀 About

静岡県浜松市からフルリモートで働く Web エンジニアです。
**React / Next.js / TypeScript のフロントエンド**を主戦場にしつつ、プロダクトによっては
**Node.js / FastAPI のバックエンド**や **AWS / Azure のインフラ**側に寄って動いてきました。

いまの関心は、**AI エージェントを個人の効率化で終わらせず、チームで同じ品質で使える形に落とすこと**。
規約はドキュメントに書くだけでは崩れるので、**Lint や CI として機械的に強制される形**にすることを重視しています。

詰まったことや設計した内容は [kt-tech.blog](https://kt-tech.blog) / [Qiita](https://qiita.com/takakou) に書いています。

<br/>

**1. フロントを軸に、必要な範囲まで自分で取りに行ける**
フロントエンドを主戦場にしつつ、時期とプロダクトによってはバックエンド API やインフラ側に寄って動いてきました。API 設計を意識した実装、サーバーレス構成の設計、IaC までひと通り自分で触れます。

**2. 開発を回す仕組みをつくる**
規約はドキュメントに書くだけだと、人が増えた瞬間に崩れます。読まないからではなく、読んでも忘れるからです。だから Lint ルールや CI として機械的に強制される形に落とすことを重視しています。ブランチ戦略・レビュールールの策定、pre-commit / GitHub Actions の整備、clone 直後に動く開発環境づくりなど。

**3. 0→1 のプロダクト開発**
個人事業主としてヒアリング・要件定義・技術選定・実装・運用まで単独で完遂した経験があります。業務委託でも立ち上げフェーズから参画し、技術選定から運用まで伴走しています。

**4. AI エージェントを開発に組み込む**
Claude Code を業務・個人開発の両方で常用。skill / subagent の設計、複数セッションの並行運用、定型作業の自動化を実践し、その設計と落とし穴を [ブログ](https://kt-tech.blog) にまとめています。

</details>
